# 中文自动化测试平台需求、架构与接口设计

版本：2.0。日期：2026-10-19。状态：已实现，验收明细见《验证记录》平台章节。本文件是最新产品基线，取代旧版“仅命令行、无需 Web 后台”的产品范围。

## 1. 目标与范围

提供本机中文 Web 测试平台，以表单管理环境、模块与常见接口/Web 用例，批量选择模块执行，查看状态、日志与报告。使用现有 Python 3.12.7、Playwright、Pytest 与本机 Edge，新增服务只依赖标准库，不安装新数据库或前端运行时。

支持本地项目、测试服务器和线上目标。平台管理服务仅监听本机回环地址；“支持线上目标”不等于管理端已具备公网多人部署能力。

| 编号 | 要求 | 实现 |
|---|---|---|
| P01 | 中文网页操作 | 工作台、模块用例、环境、执行报告、使用指南 |
| P02 | 多模块便捷测试 | 勾选多个模块，环境与类型统一选择，标签筛选 |
| P03 | 接口测试 | 表单填写方法、路径、头、JSON 请求体、状态与业务断言 |
| P04 | Web 测试 | 动作行组合、定位、输入和页面断言，可增删排序 |
| P05 | 流程复用 | 公共变量、登录流程、提取值与清理，高级配置支持联动 |
| P06 | 中文结果报告 | 实时日志、通过/失败等状态，中文 HTML/JSON 和失败附件 |
| P07 | 任务与历史 | 独立子进程，SQLite 持久化，停止与异常中断识别 |
| P08 | 保护已有业务 | 保留环境、凭证、Python/YAML 用例和既有报告，不运行用户真实测试作为开发验证 |
| P09 | 清理开发验证 | 隔离目录与模拟服务验收后删除，保留文字结论 |

## 2. 存储与执行设计

配置存储沿用 YAML：`config/environments.yaml`、`cases/**/*.yaml|yml`、`cases/_shared.yaml`。Python 业务扩展沿用 `tests`。平台新增 `.platform/history.sqlite3` 保存运行索引和日志；报告仍由执行引擎生成到配置目录。

SQLite runs 表：`id` 主键、`created/finished` 时间、`status` 状态、`payload` JSON 执行参数、`log` 最新最多约一百万字符的日志、`exit_code`、`report_id`、`result` JSON。普通列表只返回索引，不一次返回大日志和结果。

任务状态：queued → running → passed / failed / error / no_tests / skipped；停止进入 stopping → cancelled；平台异常退出后未完成任务在下次启动标为 interrupted。退出 5 归为 no_tests，退出 1 归为 failed，其他异常退出归 error；退出 0 仍需检查是否存在实际验证结果，全部跳过不归 passed。

单工作空间单平台实例、单活动任务。运行中拒绝通过页面修改环境/模块和启动第二任务。避免并发资源污染；外部 CLI 和手动文件修改不受页面锁协调，应避免同时使用。

## 3. API 通用约定

服务地址默认 `http://127.0.0.1:8765`。请求/响应为 UTF-8 JSON，除静态页面和报告资源外。

写操作请求头：

```http
Content-Type: application/json
X-Platform-Token: <从同源 /api/bootstrap 获取的令牌>
```

令牌每次平台启动重新生成。服务拒绝其他 Host、外部 Origin，不提供 CORS。写请求体限 2 MiB。令牌用于防止跨站写入，不是多人账号认证。

错误统一为 `{"error":"中文原因"}`：400 参数或配置不正确，403 来源/令牌/路径不允许，404 资源不存在，409 版本冲突或已有活动任务，500 文件/进程等操作异常。

## 4. 接口列表

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | /api/bootstrap | 初始化：version、token、config、modules、active、module_error |
| GET | /api/module?file=orders.yaml | 获取模块 file、text、data、revision |
| PUT | /api/module | 创建或保存模块/公共配置，先校验后原子替换 |
| DELETE | /api/module | 删除指定 YAML 模块，不支持删除 Python 或公共文件 |
| PUT | /api/config | 保存环境集合与默认环境，保留其他已有执行/报告配置 |
| GET | /api/runs | 最近 100 个任务索引及 active 任务编号 |
| POST | /api/runs | 校验并启动异步任务，成功返回 202 和 id |
| GET | /api/runs/{id} | 完整任务、日志、结果与报告编号 |
| POST | /api/runs/{id}/stop | 请求停止活动任务，请求体 `{}` |
| GET | /api/reports | 当前报告目录下最近 100 份有效报告摘要与 url |
| GET | /reports/{report_id}/report.html | 中文报告 |
| GET | /reports/{report_id}/result.json | 结构化结果 |
| GET | /reports/{report_id}/attachments/{file} | 已生成的 PNG 或 ZIP 附件 |

## 5. 模块保存请求

```json
{
  "file": "orders.yaml",
  "revision": "编辑已有文件时必须提供其当前版本摘要",
  "data": {
    "module": "orders",
    "name": "订单管理",
    "enabled": true,
    "cases": [{"id":"list","name":"订单列表","access":"readonly","request":{"method":"GET","path":"/api/orders"},"expect":{"status":200,"json":{"code":0}}}]
  }
}
```

新建时不传 revision。高级编辑可传 `text` YAML 字符串替代 data，text 优先。创建同名已有文件会因缺少正确 revision 被拒绝。删除传 file 与当前 revision。

平台复制全部 YAML 到独立临时校验目录，将候选内容覆盖后执行统一校验：重复标识、未知字段、类型、流程、访问模式和有效断言等。通过才原子替换原文件；失败原文件不变。公共配置固定为 `_shared.yaml`，不允许借文件名访问 cases 外部文件。

模块元数据返回 id、name、file（YAML）、source、enabled、count、各测试类型数量及用例摘要。Python 来自静态扫描，不导入执行，参数化/复杂动态标记最终以 Pytest 收集为准。

## 6. 环境保存请求

```json
{
  "revision": "当前配置版本摘要",
  "default_environment": "local",
  "environments": {
    "local": {
      "web_base_url": "http://127.0.0.1:3000",
      "api_base_url": "http://127.0.0.1:8000",
      "allow_write": true,
      "verify_tls": true,
      "allowed_origins": []
    }
  }
}
```

至少保留一个环境。默认环境必须存在；URL 为 HTTP(S)、不得包含账号密码；额外来源逐个校验。返回新 config 对象与 revision。执行/报告等其他现有配置不通过本接口改写。

## 7. 启动执行请求与结果

```json
{
  "environment": "local",
  "modules": ["orders", "users"],
  "scope": "all",
  "tags": "smoke,regression",
  "headed": false,
  "read_only": false,
  "allow_write": false
}
```

modules 至少一个有效模块；scope 为 all/api/web/workflows。tags 多项匹配任一，再与模块和范围取交集。read_only 与 allow_write 不能同时开启，allow_write 还要求目标环境已允许写入。平台不把请求拼接为 shell 命令，使用固定 Python 模块和参数数组启动进程。

后台调用原有 `framework.cli`，日志逐行持久化。报告归属以任务启动前目录集合与完成后新增的框架报告判定；因此不要同时绕过平台运行 CLI 向相同报告目录写入。

停止先向任务进程组发送中断，约 5 秒无响应后终止进程树。停止不是业务事务回滚；被测数据可能需人工检查。正常用例仍通过 cleanup 机制清理。

## 8. 展示与边界

前端静态资源在项目内，无 CDN 和构建步骤。接口文本展示经过 HTML 转义。限制报告路径为配置报告根目录内、带框架标记的运行目录，只公开 HTML/JSON/PNG/ZIP；不提供任意目录下载或 `.env` 浏览接口。

日志和报告复用字段、环境凭证与动态提取值脱敏。截图/Trace 的原始页面与网络信息仍需按测试账号和附件分享规则管理。

本版本没有用户账号、团队权限、远程执行节点、定时执行、并发压测或自动推断业务用例。后续多人部署需另外设计身份认证、权限、任务队列与隔离执行环境。

## 9. 验收

使用独立临时业务服务和工作空间，通过真实 Edge 浏览器验证创建模块/API/Web 用例、环境保存、批量运行与报告；通过平台接口验证边界、失败附件、停止、单实例、持久化和业务文件保护。临时服务与数据清理，文字结果在《验证记录》中记录，不将演示业务留在正式模块中。
