# 测试平台操作与学习指南

版本：2.0。更新日期：2026-10-19。项目：`E:\test-projectA\web`。

## 1. 现在如何启动

双击项目中的 `start-platform.cmd`。浏览器会打开：

```text
http://127.0.0.1:8765
```

保留启动窗口。关闭浏览器页签不会关闭平台；在启动窗口按 Ctrl+C 关闭平台。若有运行中的任务，平台会尝试停止它。

也可在 PowerShell 中启动，无需先激活虚拟环境：

```powershell
Set-Location E:\test-projectA\web
.\.venv\Scripts\python.exe -B -m test_platform.server
# 端口被其他程序占用时
.\.venv\Scripts\python.exe -B -m test_platform.server --port 8766
# 不自动打开浏览器
.\.venv\Scripts\python.exe -B -m test_platform.server --no-open
```

浏览器继续使用已安装的 Edge。当前升级没有新增第三方依赖，也不需要安装 Node、前端包或单独的数据库。平台 HTTP 服务与 SQLite 使用 Python 标准库；执行仍使用已经安装的 Playwright、Pytest、PyYAML 和 Jinja2。

## 2. 页面分别做什么

| 页面 | 功能 |
|---|---|
| 工作台 | 查看模块、用例、环境数量，最近报告通过率和最近执行任务 |
| 模块与用例 | 新建、编辑、复制、删除配置用例，启停模块，搜索和运行模块 |
| 环境配置 | 保存前端/后端地址、允许来源、证书校验、写入策略与默认环境 |
| 执行与报告 | 查看状态和实时日志，停止任务，打开历史中文报告、失败截图和 Trace |
| 使用指南 | 在平台内查看基本操作、已有 Python 用例与高级流程的说明 |

本版本是可以操作和执行测试的本机 Web 平台。框架代码作为内部执行引擎继续保留，日常主要操作网页。

## 3. 测试本地或线上项目

### 3.1 配置目标环境

先启动本地被测项目的前后端。在平台点击「环境配置」，选择 local：

- Web 页面地址：你的前端地址，例如 `http://127.0.0.1:3000`。
- 接口服务地址：你的后端地址，例如 `http://127.0.0.1:8000`。
- 额外允许的来源：页面确实需要的其他 API、CDN 等来源，每行一个。
- 按场景设置是否允许业务写入，点击「保存环境」。

同一套系统的登录、注册、订单、商品模块共用环境，不必切模块就改域名。另一套系统可新增一个环境名称并填写对应地址。线上使用 staging/production 或自己创建的名称，测试步骤仍填写相对路径。

HTTP/HTTPS 地址不能包含用户名密码。HTTPS 默认校验证书，测试自签名环境可以按实际需要关闭。production 默认只跑显式只读用例；线上写入需要环境允许，同时在启动测试时明确勾选「允许线上写入」。

### 3.2 建立业务模块

在「模块与用例」点击「新建模块」：标识填写 `orders`，名称填写「订单管理」。保存后进入用例管理。一份模块可放多条接口与页面用例。

标识支持中文、字母、数字、下划线、短横线，不以下划线开头。名称用于中文展示。新建模块默认启用，但没有用例时不会被认为验证通过。

模块配置保存在 `cases/<模块标识>.yaml`。普通操作不必打开文件；平台负责保存和执行前校验。可将这些 YAML 纳入项目版本管理。平台不会自动覆盖同名模块，旧页面保存时遇到版本冲突会要求刷新。

### 3.3 新建接口用例

点击「管理用例 → 新增用例」，填写：

| 字段 | 示例 | 说明 |
|---|---|---|
| 名称 | 查询订单列表成功 | 在报告中展示 |
| 标识 | list_success | 当前模块内唯一 |
| 访问类型 | 只读场景 | 真实会修改业务数据时保持写入 |
| 标签 | smoke,regression | 可选，运行时按标签筛选 |
| 请求方法 | GET | 也支持 POST/PUT/PATCH/DELETE/HEAD/OPTIONS |
| 路径 | /api/orders | 与当前环境的 api_base_url 组合 |
| 请求头 JSON | `{}` | 可填写认证头；推荐使用环境变量/公共流程引用 |
| 请求体 JSON | `{"name":"测试名称"}` | GET 通常留空，按接口要求填写 |
| 预期状态码 | 200 | 按真实接口约定填写 |
| 业务断言 JSON | `{"code":0,"data.items[0].id":1}` | 键是响应字段路径，值是预期值 |
| 耗时上限 | 2000 | 可选，单位毫秒，不等同于压测 |

保存后可继续添加其他正常、异常或边界场景，用「复制」快速建立相似用例并修改数据。查询参数可直接放在路径中；更复杂的 params、form、类型断言使用高级配置。

表单不会根据 URL 猜测正确的业务结果。首次需要依据接口文档填写字段与预期，之后反复复用。

### 3.4 新建 Web 用例

在新增用例中选择「Web 测试」，按顺序添加步骤：

1. 打开页面：右侧值填写 `/login`。
2. 填写输入框：定位方式「标签」，定位内容「用户名」，值填写测试用户名。
3. 填写密码框：定位方式「标签」，定位内容「密码」，值填写测试密码或变量引用。
4. 点击元素：定位方式「角色」，定位内容填写 `button|登录`。
5. 验证文字：右侧值填写登录成功后应出现的文字。

点击「添加步骤」增加行，「↑」上移，「×」移除。左侧选择动作，中间选择定位方式和定位内容，右侧填写路径、输入内容或预期值。打开页面、验证标题、验证地址、验证文字这几类动作只读取右侧值，不需要中间定位。

定位优先使用 test_id、label（标签）、role（角色），也支持 CSS 和文字。角色格式为 `角色|可访问名称`，例如 `button|保存`。标签、角色名称、文字精确匹配。表单填写、勾选、下拉、按键、输入值断言等操作均可组合。

至少包含一个有效断言，单纯打开页面或点击不会被当作有效验证。复杂 iframe、上传、下载、特殊认证可继续使用 Python 扩展。

## 4. 批量运行与报告

点击右上角「开始测试」：选择环境，勾选一个或多个业务模块，选择全部/接口/Web/联动范围。可按标签筛选、显示浏览器或只运行只读场景，然后点击启动。

页面自动显示任务详情，约每 1.8 秒更新状态与日志。完成后点击「打开中文报告」，在独立页签查看每条用例的结果、准备/执行/清理阶段、断言及失败证据。旧报告也可从「执行与报告 → 全部报告」打开。

| 状态 | 含义 |
|---|---|
| 准备中 / 执行中 | 后台任务尚未结束 |
| 通过 | 退出正常，至少实际执行一条普通业务用例 |
| 失败 | 断言或用例阶段失败，查看报告原因 |
| 错误 | 配置、连接、执行或报告异常 |
| 无匹配用例 | 筛选后为零，不代表通过 |
| 全部跳过 | 未启用或策略阻止等，没有普通通过/失败结果 |
| 停止中 / 已停止 | 用户请求停止；可能没有完整报告 |
| 意外中断 | 平台异常退出后，重启识别到未完成任务 |

每次只运行一个任务；运行中平台禁止再次启动或修改配置，避免地址和数据发生变化。仍应避免同时通过旧命令行运行另一批测试或在外部编辑正在使用的文件。

「停止任务」先请求中断，约 5 秒仍未退出时终止任务进程树。强制停止、断电等情况可能无法完成业务数据清理，需要检查目标系统。平台不支持把任意业务写入事务自动回滚。

## 5. 登录复用、变量和联动

在「公共流程」中编辑共享变量与登录流程；在用例「高级配置」中编辑完整 JSON 对象，在「高级模块配置」中可直接编辑 YAML。这些能力供复杂流程使用，常规接口和页面用例可用表单完成。

详细的 before、steps、cleanup、extract、use、变量及动作格式见 [多模块快速测试](多模块快速测试.md)。JSON 与 YAML 使用相同的数据结构。例如高级用例：

```json
{
  "id": "list_with_login",
  "name": "登录后查询列表",
  "access": "write",
  "before": [{"use": "sign_in"}],
  "request": {"path": "/api/orders", "headers": {"Authorization": "Bearer ${token}"}},
  "expect": {"status": 200, "json": {"code": 0}}
}
```

`sign_in` 需先在公共流程中定义，登录产生的 token 只在当前用例中使用。包含登录等写入动作时要按实际读写设置 access。账号密码建议放 `.env`，用 `${ENV:名称}` 引用，平台不提供 `.env` 内容查看接口。`${uuid}` 和 `${timestamp}` 每条用例独立生成。

同一用例组合 API 与页面步骤自动归为联动场景。API 登录与浏览器上下文互相独立，不会自动共享 Cookie；页面登录使用 Web 流程或合适的 storage_state。

## 6. 原有业务用例与文件

既有 `tests/api/test_login.py`、`tests/api/test_register.py`、`tests/web/test_register_web.py` 保留，会在模块列表中显示为 Python 扩展。可以选择执行，但平台不会直接编辑或删除这些代码。默认按文件名去掉 `test_` 推断模块；复杂动态标记和参数化的实际数量以执行收集为准。

环境继续在 `config/environments.yaml`；正式结果仍在配置的报告目录；`.env` 和已有报告不因升级删除。不要将相同业务同时放在 YAML 和 Python 中又全选执行，除非希望它们分别运行。

## 7. 架构每层的职责

```text
浏览器页面（HTML / CSS / JavaScript）
  ↓ 同源 JSON API
本机 HTTP 服务（路由、来源与令牌校验、静态资源）
  ↓
平台服务层（环境/模块管理、校验、版本冲突、任务控制）
  ├─ YAML 文件：环境与用例
  ├─ SQLite：执行任务、日志与结果索引
  └─ 独立 Python 子进程
       ↓ 原有统一执行入口
     Pytest + Playwright → API / Edge → 中文 HTML / JSON / 附件
```

| 文件 | 细节与职责 |
|---|---|
| start-platform.cmd | 定位本项目 Python、切换工作目录，启动平台，不安装或修改系统 Python |
| test_platform/server.py | ThreadingHTTPServer 接收请求；限制本机 Host、Origin 和写操作令牌；限制请求体 2MB；只公开列明的静态资源与报告类型 |
| test_platform/service.py | Platform 统一处理环境、模块、执行任务；RLock 保护操作，文件锁限制单实例；临时目录校验后原子替换文件，SHA-256 revision 检查多页编辑冲突 |
| test_platform/store.py | SQLite 使用 WAL 与连接超时；保存状态、参数、日志、退出码、报告编号及结果，重启将未完成任务标记中断 |
| static/index.html | 中文导航、工作区、弹窗和状态提示的页面结构 |
| static/style.css | 工作台布局、表单、卡片、状态样式及窄屏适配，无外部 CDN |
| static/app.js | 页面渲染、表单/步骤编辑、模块选择、API 请求、状态轮询；展示内容先转义，不把配置当脚本执行 |
| framework/cli.py | 平台通过独立子进程调用它，统一处理配置、范围和用例，兼容已有 CLI |
| framework/declarative.py | 将 YAML 变成 Pytest 用例，合并变量、展开流程、执行 API/Web 步骤与清理 |
| framework/fixtures.py / lifecycle.py | 为每条用例管理独立 API/浏览器上下文，清理回调先于上下文释放 |
| framework/settings.py / security.py | 配置合并、访问来源限制、URL/凭证/动态提取值脱敏 |
| framework/reporting/* | 合并执行阶段、生成中文结果与报告，保存失败截图/Trace，清理超期框架报告 |

任务数据流：提交 → 校验环境与模块 → SQLite 建立准备中记录 → 工作线程启动独立执行进程 → 增量保存中文日志 → 读取新报告 → 根据退出码和实际结果归类 → 页面轮询展示。HTTP 请求不会一直等待业务测试结束。

不在 HTTP 服务线程直接调用 Pytest，避免重复运行和 Playwright 同步 API 相互影响。多模块目前顺序执行；页面的「批量」表示一次选择多个模块，不代表并发压测。

## 8. 数据、维护和边界

- `.platform/history.sqlite3` 是平台历史数据库，另有 SQLite WAL/SHM 和单实例锁文件；已加入 .gitignore。关闭平台后备份该目录。
- `cases` 与 `config` 是正式业务定义，建议版本管理；保存会保留未编辑的数据字段，但 YAML 注释格式可能重新排版。
- 报告最多在平台列表显示最近 100 份；任务列表显示最近 100 条。完整数据库记录未因分页显示限制被删除。
- 旧报告依旧按配置的保留天数管理，数据库记录不保证附件永久存在。附件删除后显示不存在。
- 当前仅监听 127.0.0.1，无用户登录、权限分工、团队协作或远程执行节点。测试目标可以是线上服务，但管理平台供本机使用。
- 截图和 Trace 可能含原始页面及网络数据，使用测试账号并限制分享范围。
- 本平台不自动启动或部署被测项目，不做压测，也不根据域名自动猜测正确业务行为。

平台接口详见 [平台需求与接口设计](平台需求与接口设计.md)，本次实施步骤见 [平台开发进度](平台开发进度.md)，验收结果见 [验证记录](验证记录.md)。
