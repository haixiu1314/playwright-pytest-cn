# 自动化测试项目学习指南

当前日常入口已升级为 Web 测试平台，请先读 [平台操作与学习指南](平台操作与学习指南.md)。本文保留为内部执行引擎的学习与扩展资料，CLI 仍兼容，不是现在使用平台的必经步骤。

本文按“先运行，再理解，再扩展”的顺序说明整个项目。代码示例仅用于学习，未作为演示测试文件留在正式目录中。被测业务的地址、选择器、接口路径、字段和预期值必须替换成真实内容。

## 1. 项目解决什么问题

Pytest 负责发现用例、管理夹具、执行断言和报告阶段事件；Playwright 负责浏览器操作和 HTTP 请求；项目自身负责配置、环境边界、中文结果、失败证据与离线报告。

接口测试不是必须启动浏览器。`APIRequestContext` 可以单独发请求；只有使用 `page` 夹具时才会启动 Chromium 或 Edge。这能够降低只测接口时的资源占用。

框架不会自动理解你的业务，也不会扫描一个网址后自动证明所有功能正确。你需要定义“做什么”和“什么结果算正确”，框架负责可靠执行和汇总。

## 2. 分层架构与职责

| 层 | 文件或目录 | 输入 | 输出 | 为什么单独分层 |
| --- | --- | --- | --- | --- |
| 执行入口 | `framework/cli.py`、`run.ps1` | 命令行参数 | Pytest 执行与退出码 | 所有环境统一入口，避免忘记加载报告插件 |
| 配置层 | `settings.py`、YAML、`.env` | 环境、地址、超时、凭证 | Settings 对象 | 切换目标无需改业务代码 |
| 用例层 | `tests/` | 真实业务场景 | 断言结果 | 测试意图与基础设施分开 |
| 页面层 | `pages/` | 页面、路径、表单值 | 浏览器行为及页面状态 | 页面结构变化时集中维护定位 |
| 接口层 | `api_client.py` | HTTP 方法、路径、请求参数 | Playwright 响应 | 统一认证、地址校验与步骤记录 |
| 断言与步骤层 | `assertions.py`、`steps.py` | 实际与预期 | 中文步骤、断言异常 | 失败报告能说明差异 |
| 生命周期层 | `fixtures.py`、`lifecycle.py` | 用例资源 | 初始化、释放和清理结果 | 用例之间不共享可变状态 |
| 报告层 | `reporting/` | Pytest 三阶段结果 | HTML、JSON、附件 | 展示方式与业务用例分开 |

一次运行的调用链：命令行 → 读取 Settings → 创建 Reporter → `pytest.main` → 收集筛选 → 连通性检查 → setup → call → teardown → 汇总最终状态 → 写 HTML/JSON → 清理过期报告 → 返回退出码。

## 3. 根目录文件逐项说明

### 3.1 pyproject.toml

声明项目名称、Python 下限、依赖兼容范围以及打包规则。框架的包名为 `automation-framework`，不与任何演示业务绑定。`setuptools` 发现 `framework` 和 `pages` 包，并将 Jinja2 模板打包。可编辑安装 `-e .` 使修改源代码后无需重复安装。

### 3.2 requirements.lock.txt

冻结实际安装的第三方依赖版本。Pytest、Playwright 的间接依赖也在其中。它用于重建已验证环境，不包含虚拟环境自身或浏览器二进制。升级 Playwright 后需要重新安装相匹配的浏览器并重新验证。

### 3.3 pytest.ini

`testpaths` 声明默认用例目录；`--strict-markers` 防止标记拼写错误被静默忽略；`xfail_strict=true` 使已知失败用例意外通过时产生失败，以提醒维护者删除过期的已知问题标记。

标记 `api/web/workflow` 决定范围，`readonly/write` 决定执行策略，`title` 决定中文名称。`workflows` 是目录和命令参数名称，单条用例标记使用单数 `workflow`。

### 3.4 .env.example 与 .gitignore

`.env.example` 只有变量名，不保存真实凭证。复制为 `.env` 后填写；系统已设置的环境变量优先，文件不会覆盖它们。`.gitignore` 排除虚拟环境、浏览器、报告、缓存及凭证文件，但 Git 忽略规则不代表文件加密。

### 3.5 run.ps1 与 install-browser.ps1

`run.ps1` 使用项目自己的解释器、浏览器路径和 UTF-8 输出，进入项目目录执行，最终保留 CLI 退出码。`install-browser.ps1` 将浏览器装入 `.browsers`，下载失败则说明如何改用 Edge。它不会安装或更新系统 Edge。

两个 PowerShell 脚本使用 UTF-8 BOM，兼容 Windows PowerShell 5 的中文脚本解析；Python、Markdown 和 HTML 使用普通 UTF-8。

## 4. 配置层的每个字段

| 字段 | 作用 | 注意点 |
| --- | --- | --- |
| `project_name` | 终端报告对应的项目展示名称 | 不会改变 Python 函数名 |
| `default_environment` | 未传 `--env` 时使用的环境 | 必须存在于 environments |
| `web_base_url` | 页面相对路径的解析起点 | 地址有路径前缀时，`open('child')` 保留前缀，`open('/child')` 从域名根开始 |
| `api_base_url` | 接口相对路径的解析起点 | 与页面可不同域名或端口 |
| `allow_write` | 环境是否允许写入 | false 时所有环境强制只读 |
| `verify_tls` | 校验证书 | 默认 true；仅在清楚本地自签名证书情况时修改 |
| `allowed_origins` | 额外允许的精确 origin | 用于 CDN、认证或前端调用另一个接口域名 |
| `browser` | chromium 或 msedge | 第一版不支持 Firefox/WebKit |
| `headless` | 默认是否无头运行 | `--headed` 可以强制显示窗口 |
| `timeout_ms` | 单次 Playwright 操作和断言超时 | 单位毫秒，不是整个项目时间上限 |
| `retries` | 自动重试次数 | 第一版必须为 0，避免用重试掩盖不稳定 |
| `directory` | 正式报告根目录 | 每次执行建立独立 run_id 目录 |
| `locale` | 报告语言 | 第一版固定中文，不提供多语言切换 |
| `screenshot_on_failure` | 是否保留失败截图 | 截图可能包含页面敏感内容 |
| `trace` | off 或 retain-on-failure | 成功用例不保留 Trace |
| `retention_days` | 历史报告保留天数 | 最新一次报告不会因过期清理被删除 |
| `sensitive_fields` | 日志额外脱敏字段名 | 可根据业务新增，如手机号对应字段 |

`Settings` 是运行期配置对象。`load_settings` 校验 URL、关键布尔值、超时、浏览器、保留天数等，配置错误用中文给出原因。`origin` 将 URL 规范为协议、主机、有效端口，例如 https 默认端口是 443。`resolve_url` 负责相对地址解析后再次检查环境边界；不允许通过绝对地址意外访问另一个环境。

环境名 `production` 触发额外的显式线上写入确认规则。如果新增另一个线上环境名，应设置 `allow_write: false`；第一版不会通过环境名猜测它是否线上。

## 5. 框架源码逐文件说明

### 5.1 framework/cli.py

`parser()` 定义帮助、环境、范围、显示浏览器、只读、允许写入、报告目录、配置路径、用例路径和名称筛选。`main()` 统一 UTF-8，加载配置并调用 Pytest。`--read-only` 和 `--allow-write` 互斥，参数错误返回 4。

通过 `-p no:terminal` 关闭 Pytest 英文终端摘要，由 Reporter 输出中文，但保留异常技术原文。通过 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` 禁止环境中的第三方插件自动改变执行行为。需要新插件时应显式设计与接入，而不是依赖个人机器的隐式配置。

`--tests` 默认是项目 tests，也可指定用例文件或临时目录；`-k` 沿用 Pytest 名称表达式。项目串行执行，不支持 xdist 并行。命令应在新进程中运行，不建议在同一个 Python 进程里反复调用 `main()`。

### 5.2 framework/api_client.py

`ApiClient` 包装 Playwright 请求上下文。`request` 将方法转大写、检查只读策略、解析路径、阻止自动重定向，再调用 `context.fetch`。方便方法 `get/post/put/patch/delete` 最终均复用 request，不按某个测试项目命名。

`json=` 是本框架提供的便利参数，会转换为 Playwright 的 `data=`；字典会以 JSON 发送。查询条件使用 `params=`，请求头使用 `headers=`。响应对象保留原生 API，例如 `response.status`、`response.json()`、`response.headers`。

`last_duration_ms` 记录最后一条请求耗时。框架默认不记录响应正文，降低敏感内容和报告体积；报告包含状态码、耗时及脱敏后的请求摘要。需要查看某字段时通过断言提供差异。

301/302 不会自动跟随。若业务预期重定向，先断言重定向状态码，再取 Location 并通过 ApiClient 显式请求，以便再次校验目标环境。

### 5.3 framework/assertions.py

`assert_status` 比较 HTTP 状态码。`json_value` 从 JSON 中提取简单路径，支持字典键与数组下标；不支持通配符、递归查询、键名本身含点的完整 JSONPath。响应不是 JSON、字段不存在、数组越界和类型不匹配均给出中文原因。

`assert_json_value` 比较业务值；`assert_json_type` 使用严格类型比较，避免 Python 中 bool 是 int 子类带来的混淆；`assert_duration` 比较最后请求与阈值。真正的业务断言应同时考虑状态码和业务字段，HTTP 200 不必然代表业务成功。

### 5.4 framework/steps.py

`step` 是上下文管理器，进入时记录标题，退出时记录耗时。内部异常标记步骤失败并重新抛出，不吞异常。`ContextVar` 关联当前用例的步骤列表，避免把步骤写入其他用例。它不代表本项目已经支持多线程或并行执行。

### 5.5 framework/security.py

`redact` 递归处理字典、列表和字符串，隐藏常见敏感键、环境中的账号密码和 Token、Bearer 值。额外字段由配置提供。`safe_url` 隐藏整个查询串，防止自定义查询密钥泄露。

这不是通用数据防泄露系统。截图、Trace、任意业务断言中没有明确标识的个人信息不会被自动可靠擦除。应使用测试账号和专用数据，分享报告前检查附件。异常原文经过文本脱敏后再输出。

### 5.6 framework/lifecycle.py

`CleanupRegistry` 保存清理回调与参数。`register` 登记，`close` 按后进先出顺序执行。某个回调失败后继续执行其他回调，最后统一抛出中文异常。

创建资源后立即登记其清理函数。不要登记删除业务全表或所有文件的操作，只登记本轮确实创建的资源 ID。清理函数必须有明确权限与幂等性设计，失败后可以人工处理。

### 5.7 framework/fixtures.py

`settings` 和 `playwright_runtime` 是 session 级资源，整轮复用配置和 Playwright 运行时。`api_client` 每条用例创建独立请求上下文，并从环境变量读取认证。`page` 每条用例创建浏览器和独立上下文，避免 Cookie、页面和登录变更串扰。

浏览器上下文通过 route 拦截 HTTP 请求，校验每个目标 origin；只读模式还阻止非 GET/HEAD/OPTIONS 请求。Service Worker 被禁止，避免绕过普通路由。未允许的 CDN 或认证地址会导致失败，而不是静默忽略。该功能不代替操作系统级网络隔离，直接使用第三方网络库、自建浏览器或 WebSocket 的业务扩展需要另行审查边界。

`page` 启动 Trace；主体失败时 Reporter 在页面仍存活时截图；页面夹具退出时保存失败 Trace，再释放上下文和浏览器。`cleanup_registry` 夹具结束时逆序清理，失败会被记录到 teardown。

如同时使用 page、api_client、cleanup_registry，应在函数参数中先请求 page 和 api_client，再请求 cleanup_registry，使清理回调先执行、浏览器和接口上下文后释放。更复杂场景建议创建业务夹具显式依赖这些资源。

### 5.8 framework/reporting/models.py

`new_case` 为每条用例创建结果结构。`final_status` 合并阶段：setup/teardown 失败优先为错误，call 失败为失败，xfail 为预期失败，跳过单列，只有主体通过且清理无错误才是通过。严格 xfail 意外通过会由 Pytest 产生 call 失败。

### 5.8.1 framework/browser.py

`launch_options` 统一处理无头/可见窗口及浏览器路径。Chromium 使用 Playwright 的版本化下载目录；Edge 依次检查系统级和用户级安装路径，找到后设置 `executable_path`。当前本机系统级 Edge 已通过实际驱动验证，避免只依赖默认 channel 对安装位置的猜测。

### 5.9 framework/reporting/plugin.py

`Reporter` 通过 Pytest hooks 工作。构造时生成时间加随机后缀的运行 ID，防止同秒覆盖。`pytest_configure` 把本轮配置挂到 Pytest config，供夹具读取。

`pytest_collection_modifyitems` 根据标记或所在目录筛选范围，检查只读策略，并对需要运行的目标做 TCP/TLS 连通性检查。连通只说明服务可连接，不代表业务接口正确；业务正确性由用例断言负责。被策略跳过的用例仍进入报告并说明原因。

该收集 hook 在 Pytest 名称筛选之后执行，`pytest_deselected` 还会移除取消选中的条目。因此 `-k` 不会把其他未运行的条目计入错误，按 `--scope` 筛选也不会污染报告统计。

`pytest_runtest_setup` 绑定当前步骤上下文。`pytest_runtest_makereport` 收到每条用例的 setup/call/teardown 报告，在 teardown 后才输出最终中文状态。截图名使用 nodeid 的哈希，避免中文或参数中的特殊字符导致非法文件名。

`pytest_collectreport` 记录导入和收集错误；`pytest_keyboard_interrupt` 记录中断；`pytest_internalerror` 记录框架内部问题。`pytest_sessionfinish` 统计、生成报告、输出位置、清理过期报告。未完整执行的条目会标为错误，不会猜测为通过。

### 5.10 framework/reporting/builder.py

Jinja2 开启自动 HTML 转义，异常或标题包含脚本字符也作为文本显示。JSON 使用 `ensure_ascii=False` 保留中文。文件先写临时文件再替换，降低写一半留下无效文件的概率；系统强杀或磁盘故障仍可能造成不完整结果。

报告目录带 `.automation-report` 标识，历史清理只删除报告根目录直接子目录中带此标识的过期目录，跳过符号链接和 junction，保留当前运行。不会递归搜索其他位置删除报告。

### 5.11 HTML 模板

模板使用本地 CSS 与 JavaScript，无外部 CDN。顶部显示环境、时间、退出码和统计卡片；中间提供搜索与状态筛选；每条用例可展开步骤、三个阶段、错误和附件。JavaScript 只根据已有文字筛选，不动态执行用户提供的内容。

### 5.12 pages/base_page.py

提供打开页面、按 label 填表、按 role 点按钮、断言标题和文字的方法。实际业务通常增加 `LoginPage`、`RecordPage` 等真实页面对象，避免一个万能类堆积所有页面行为。定位优先 role/label/test-id，不写脆弱的绝对 XPath，也不靠 `sleep` 等待。

## 6. 状态、通过率与退出码

“通过”表示该条用例的准备、主体和清理均完成；“失败”表示主体断言或操作失败；“错误”表示准备/清理失败或执行不完整；“跳过”不代表业务正确；“预期失败”表示已知问题。

同一条用例主体和清理都失败时，最终算一条错误，报告仍保留两阶段原因。通过率为通过数除以通过、失败、错误之和。没有可统计分母时显示“无可统计结果”。

| 退出码 | 含义 |
| --- | --- |
| 0 | 所选执行完成且无普通失败；全跳过时会额外明确提示未实际验证业务 |
| 1 | 用例失败，包含严格 xfail 意外通过及清理错误 |
| 2 | 执行中断或收集错误 |
| 3 | 内部错误或报告生成失败 |
| 4 | 参数、配置或执行前连通性校验错误 |
| 5 | 没有可执行用例 |

## 7. 正式用例编写原则

每条用例独立准备数据，避免依赖其他用例先运行。中文标题写业务意图，函数名写能力，不把演示项目名嵌进每个函数。参数化 id 使用可读描述。业务写入场景标记 write，并登记清理；只读标记由实际行为决定。

不要把接口返回值直接当成预期值，也不要为了让报告全绿而删除有效断言。若测试失败，要结合需求判定业务代码还是用例错误。

## 8. 三类用例写法

以下示例不保证适用于你的项目；`/records`、页面标题与字段均需替换。代码块保留在学习文档中，正式目录没有演示用例。

### 8.1 接口用例

在 `tests/api/` 下创建 `test_records.py`：

```python
import pytest
from framework.assertions import assert_status, assert_json_value, assert_json_type

@pytest.mark.api
@pytest.mark.readonly
@pytest.mark.title("记录列表返回成功且数据结构正确")
def test_list_records(api_client):
    response = api_client.get("/records", params={"page": 1})
    assert_status(response, 200)
    assert_json_value(response, "code", 0)
    assert_json_type(response, "data.items", list)
```

### 8.2 页面用例

在 `tests/web/` 下创建对应文件：

```python
import pytest
from pages.base_page import BasePage

@pytest.mark.web
@pytest.mark.readonly
@pytest.mark.title("首页显示预期标题")
def test_home_title(page, settings):
    home = BasePage(page, settings)
    home.open("/")
    home.assert_title("你的实际页面标题")
```

需要验证表单时使用 `home.fill('字段标签', '值')` 和 `home.click('按钮名')`，并断言结果。若操作会写业务数据，应改为 write，不应标成 readonly。

### 8.3 接口准备、页面验证与清理

```python
import pytest
from framework.assertions import assert_status
from framework.steps import step
from pages.base_page import BasePage

@pytest.mark.workflow
@pytest.mark.write
@pytest.mark.title("创建记录后在列表展示")
def test_record_visibility(page, api_client, cleanup_registry, settings):
    response = api_client.post("/records", json={"name": "本轮唯一名称"})
    assert_status(response, 201)
    record_id = response.json()["data"]["id"]

    def remove_record():
        result = api_client.delete(f"/records/{record_id}")
        assert_status(result, 204)

    cleanup_registry.register(remove_record)
    with step("在页面确认新记录出现"):
        view = BasePage(page, settings)
        view.open("/records")
        view.assert_text("本轮唯一名称")
```

真实用例用 UUID 或运行编号生成唯一名称；示例中的固定字符串只说明结构。清理回调中也需要验证删除成功，单纯发送 DELETE 并不保证数据已删除。

### 8.4 参数化与登录

`@pytest.mark.parametrize('value', [...], ids=['合法输入', '边界输入'])` 可以复用用例逻辑。登录建议写成业务夹具：依赖 page 和 settings，从 `os.environ` 读取凭证，操作登录并断言登录成功，再把已登录页面提供给用例。若通过 storage_state 复用登录，注意过期时间、账号权限和环境对应关系。

## 9. 报告与临时文件管理

正式结果保存在 `reports/<run_id>/`：report.html 是给人看的，result.json 是给程序看的，attachments 放截图和 Trace。分享时复制整个目录。默认保留 7 天历史结果，最新一次正式报告保留。

框架开发验证放在 `.runtime/verification/<run_id>/`，验证结束删除用例、模拟服务、配置、数据、截图和报告。开发验证的结论记录在文档中，不保留可执行临时测试项目。正式业务用例与正式报告不在“开发完成就删除”的范围内。

## 10. 常见问题与扩展边界

- 没有用例：先用 `--list-modules` 检查模块，再添加或启用真实 YAML/Python 用例；仅设置域名不会自动生成业务用例。
- 连接失败：先启动业务服务，检查端口、域名和代理；框架不自动启动业务项目。
- 页面缺资源：检查额外 origin 是否加入 allowed_origins，尤其前端 API、CDN 和登录服务。
- 浏览器未安装：运行 install-browser.ps1，或改 browser 为 msedge；不要混用其他 Playwright 版本下载的浏览器目录。
- 终端乱码：使用本项目 CLI 的 UTF-8 输出；重定向读取日志时指定 UTF-8。
- 页面操作超时：优先检查定位、页面状态和断言，必要时调整 timeout_ms，不先增加固定 sleep。
- 全部跳过：检查 readonly/write 与环境策略，不能把跳过当成功。
- 清理失败：按报告中的具体资源人工处理，再修复清理函数；不要隐藏 teardown 错误。
- 想接 CI：使用 CLI 退出码判定任务结果，并归档整份运行目录。
- 想并行或重试：需要重新设计隔离、报告聚合和资源唯一性，第一版没有隐式支持。
- 想测性能：本框架的请求耗时阈值不代替专业压测。
- 业务使用 WebSocket、下载、上传、iframe、弹窗或特殊身份认证：可在真实页面对象和业务夹具中使用 Playwright 原生 API，额外协议与认证策略需单独验证。

实际安装路径、验证结果与开发过程，分别查看同目录的环境、验证和进度文档。

## 11. 多模块配置驱动升级

当前支持 `cases/*.yaml`、公共变量与流程、提取值、清理步骤、多模块批量筛选和 `quick.cmd` 中文菜单。原有 Python 用例继续使用，普通新增模块优先填写 YAML。详细操作、字段说明、完整示例、架构每层与各文件的作用见 [多模块快速测试](多模块快速测试.md)。

新增文件包括 `framework/declarative.py`（模型、收集与步骤执行）、`framework/modules.py`（目录与模板）、`framework/quick.py`（交互菜单）、`quick.cmd`（双击入口）、`cases/_shared.yaml`（公共变量和流程）。`cli.py` 统一收集两种用例；报告插件统一筛选和汇总，避免快捷入口与命令行结果不一致。
