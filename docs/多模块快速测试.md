# 多模块快速测试与实现说明

更新日期：2026-10-19。项目目录：`E:\test-projectA\web`。

## 1. 日常使用只做这些

本项目已升级为中文 Web 测试平台，默认双击 `start-platform.cmd` 操作网页。普通用例可通过表单添加，详见 [平台操作与学习指南](平台操作与学习指南.md)。本文介绍内部 YAML 模型和旧 CLI 的高级兼容用法。

1. 为一个被测系统配置一次环境域名和端口。模块之间共用环境。
2. 为每个业务模块填写一个 YAML 文件。一个文件中可以包含多个接口、页面或联动用例。
3. 推荐在 Web 平台中选择环境、多个模块和范围并运行；也可使用兼容入口 `quick.cmd`。
4. 下次回归复用这些用例，无需重写。业务路径或预期结果改变时才维护对应配置。

环境不是模块。登录、注册、订单、商品通常共用同一个环境，分别填写 `/login`、`/register`、`/orders` 等相对路径。前端域名写 `web_base_url`，接口域名写 `api_base_url`。不同被测系统可以增加不同环境名称；每个名称对应一组服务地址。

第一次描述业务步骤仍需要时间，框架无法仅凭网址推断字段、定位器和正确结果。配置驱动减少重复代码，主要收益来自后续多模块回归。

## 2. 启动与批量执行

在 PowerShell 中执行：

```powershell
Set-Location E:\test-projectA\web
# 中文选择菜单，也可双击 quick.cmd
.\.venv\Scripts\python.exe -m framework.quick
# 只列模块，不访问被测系统、不运行用例
.\.venv\Scripts\python.exe -m framework.cli --list-modules
# 创建模板：不会覆盖同名文件
.\.venv\Scripts\python.exe -m framework.cli --new-module orders
# 一次执行多个模块；示例名称须已在你的项目中存在
.\.venv\Scripts\python.exe -m framework.cli --env local --module login,register,orders
# 所有模块的接口用例
.\.venv\Scripts\python.exe -m framework.cli --env local --scope api
# 指定模块的页面用例，显示浏览器
.\.venv\Scripts\python.exe -m framework.cli --env local --module orders --scope web --headed
# 所有模块中带 smoke 标签的用例
.\.venv\Scripts\python.exe -m framework.cli --env staging --tag smoke
```

模板生成在 `cases/orders.yaml`，初始 `enabled: false`。按真实接口文档和页面填写后改为 `true`。模板中的两条检查都是占位示例，不代表你的业务已经完成测试。

`--module` 使用文件内的 `module` 标识，多个用英文逗号分隔。`--tag smoke,regression` 匹配任意一个标签。模块、标签、范围和 `-k` 同时提供时取交集。`-k` 匹配 Pytest 用例标识；中文展示标题不一定是可匹配标识。

默认同时收集 `tests` 下的 Python 用例和 `cases` 下的 YAML 用例。相同业务如果两处都写了，会分别执行。`--tests` 改 Python 收集路径，`--case-dir` 改 YAML 根目录；两个参数互不替代。

## 3. 一个模块覆盖多个接口

以下仅为格式说明，须替换成你的真实业务数据与断言：

```yaml
module: orders
name: 订单模块
enabled: true
variables:
  page_size: 10
cases:
  - id: list_orders
    name: 查询订单列表
    access: readonly
    tags: [smoke, regression]
    request:
      method: GET
      path: /api/orders
      params:
        pageSize: ${page_size}
    expect:
      status: 200
      json:
        code: 0
      types:
        data.items: list
      max_ms: 2000
  - id: missing_order
    name: 查询不存在的订单
    access: readonly
    request:
      path: /api/orders/not-existing
    expect:
      status: 404
```

`module` 在 YAML 目录中必须唯一，`id` 在当前模块内必须唯一。支持中文、字母、数字、下划线和短横线。`name` 是中文报告名称。`enabled` 可用于整个模块或单条用例，未启用显示跳过。

`access` 为 `readonly` 或 `write`，未填写默认 `write`。仅真正无业务写入的场景才声明只读。生产环境默认只跑显式只读用例；写入需要配置 `allow_write: true` 并在 CLI 明确使用 `--allow-write`。快捷菜单不开放线上写入选项。

接口请求支持 `method/path/params/headers` 和请求体 `json/data/form`；三种请求体只能选一种。默认方法 GET，支持 POST、PUT、PATCH、DELETE、HEAD、OPTIONS。不会自动跟随接口重定向。

`expect` 支持：`status` 状态码、`json` JSON 路径等值比较、`types` 类型比较、`contains` 正文包含文字、`headers` 响应头等值比较、`max_ms` 本次请求耗时上限。JSON 路径支持 `data.items[0].id`，不支持通用 JSONPath 表达式。类型名为 `str/int/float/bool/list/dict/null`。响应头名称使用小写。

每条用例在准备或主体阶段必须有有效断言，避免仅打开页面或发请求就算通过。多个数据组合可以在同一文件中增加多条用例；复杂参数化仍可使用原有 Pytest。

## 4. 公共登录、变量传递与清理

把可复用流程写在 `cases/_shared.yaml`：

```yaml
variables:
  account: ${ENV:TEST_ACCOUNT}
flows:
  sign_in:
    - api:
        method: POST
        path: /api/login
        json:
          username: ${account}
          password: ${ENV:TEST_PASSWORD}
        expect:
          status: 200
          json:
            code: 0
        extract:
          token:
            path: data.token
            sensitive: true
```

凭证填到项目 `.env`，沿用 `名称=值` 格式，不提交版本库。每条需要登录的用例通过 `before` 复用流程：

```yaml
module: records
name: 记录管理
cases:
  - id: create_record
    name: 创建后能查询并清理
    access: write
    before:
      - use: sign_in
    steps:
      - api:
          method: POST
          path: /api/records
          headers: {Authorization: "Bearer ${token}"}
          json: {name: "自动化_${uuid}"}
          extract: {record_id: data.id}
          expect: {status: 201}
      - api:
          path: /api/records/${record_id}
          headers: {Authorization: "Bearer ${token}"}
          expect:
            status: 200
            json: {data.id: "${record_id}"}
    cleanup:
      - when_defined: record_id
        api:
          method: DELETE
          path: /api/records/${record_id}
          headers: {Authorization: "Bearer ${token}"}
          expect: {status: 204}
```

流程定义也可放在模块的 `flows` 中，同名时覆盖公共流程。`use` 可嵌套引用；循环引用会提前报配置错误。

变量优先级为公共变量 → 模块变量 → 用例变量。`${uuid}` 与 `${timestamp}` 每条用例独立生成，可用于防重。完整占位符保留原始类型，例如整数 ID；嵌在文字中转换为字符串。`${ENV:名称}` 读取环境变量，缺少时明确报错。

`extract` 在收到响应后、验证断言前执行，便于主体断言失败时仍可清理已创建的记录。提取值供后续步骤使用；同一步骤的配置在请求前统一解析，不能在该步骤的 `expect` 中引用刚提取的值。各用例不共享提取变量和浏览器上下文，不能依赖先执行登录用例给另一个用例传 token。

`cleanup` 无论准备或主体成功与否都会尝试执行，发生一项清理错误仍继续剩余清理步骤，最后将清理失败计入错误。`when_defined` 可加在普通步骤、流程引用或清理步骤上，只在变量存在时执行。清理接口也应断言返回值。服务器已经创建数据但响应丢失、ID 未能提取时仍需按业务设计补偿方案。

带 token/password/secret/cookie 名称的提取变量会自动脱敏；其他敏感提取值使用 `{path: data.xxx, sensitive: true}`。终端、HTML 和 JSON 隐藏动态提取的敏感值。截图和 Trace 可能包含页面及网络原始数据，使用专门测试账号并妥善保管附件。

## 5. Web 用例与接口页面联动

```yaml
module: profile
name: 个人资料
cases:
  - id: edit_profile
    name: 修改资料后显示成功
    access: write
    steps:
      - web: {action: goto, path: /profile}
      - web: {action: fill, label: 昵称, value: 自动化用户}
      - web: {action: click, role: button, name: 保存}
      - web: {action: assert_text, text: 保存成功}
```

登录页面同样可以定义成公共 Web 流程，然后 `before: [{use: 流程名}]` 复用。

支持的页面动作：

| 动作 | 必填数据与效果 |
|---|---|
| goto | path；使用环境的 web_base_url 打开页面 |
| fill | 定位字段、value；填写输入框 |
| click | 定位字段；点击元素 |
| check / uncheck | 定位字段；勾选或取消 |
| select | 定位字段、value；选择原生下拉框选项的值 |
| press | 定位字段、key；例如 Enter |
| assert_text | text；验证精确匹配的文字可见 |
| assert_title | value；验证完整页面标题 |
| assert_url | path；验证完整解析后的页面地址 |
| assert_visible / assert_hidden | 定位字段；验证元素状态 |
| assert_value | 定位字段、value；验证输入框内容 |

定位字段选一种：`test_id`、`label`、`role`（可配 `name`）、`selector` 或 `text`。优先使用稳定的 test_id、表单标签和角色。`label/role+name/text` 精确匹配。`assert_text` 自身按 text 定位；需要 CSS 限定时可先用 `assert_visible`，复杂组合交给 Python。

同一用例的步骤混合 `api` 和 `web`，会自动归为联动 `workflow`，用 `--scope workflows` 或 `all` 执行。接口请求上下文与浏览器上下文独立：通过接口登录不会自动让页面登录。需要页面登录流程、合适的 storage_state 或 Python 扩展。

前端调用另一个源的 API、CDN 等时，在环境 `allowed_origins` 中填确实需要的源。相对路径以 `/` 开头从域名根目录解析；如果 base_url 带有路径前缀且想保留它，应使用不以 `/` 开头的路径。

## 6. 与原有 Python 用例共存

原有 `tests/api/test_login.py`、`tests/api/test_register.py`、`tests/web/test_register_web.py` 保持原样。未标记模块的 Python 用例按文件名去掉 `test_` 推断模块，例如 `register_web`。希望接口、页面归同一模块时，可自行在函数、类或文件级增加 `pytest.mark.module("register")`。

```python
import pytest

@pytest.mark.module("orders")
@pytest.mark.tag("smoke")
@pytest.mark.api
@pytest.mark.readonly
def test_list(api_client):
    assert api_client.get("/api/orders").status == 200
```

列出模块采用静态扫描，不导入或执行 Python。复杂动态标记、类/文件级模块覆盖和动态生成用例以实际执行收集为准；此时 CLI 可直接填写真实标记名称，菜单列表可能不能完整反映这些动态结构。

## 7. 架构每层的作用

| 层 | 文件 | 责任 |
|---|---|---|
| 快捷交互 | quick.cmd、framework/quick.py | 选择环境、多模块和范围，通过子进程调用统一 CLI；不维护第二套执行逻辑 |
| 命令调度 | framework/cli.py | 参数解析，加载环境/YAML，设置筛选，启动 Pytest 与报告插件 |
| 模块管理 | framework/modules.py | 静态列出模块、生成禁用模板；拒绝覆盖已有文件 |
| 声明式模型 | framework/declarative.py 的 load_specs/CaseSpec | 校验字段、合并变量、展开流程、推断 api/web/workflow，配置错误在执行前返回 |
| 用例收集 | 同文件 YamlPlugin/YamlFile | 将每条 YAML 用例转换为 Pytest Function，设置模块、标签、读写和标题标记 |
| 步骤执行 | 同文件 resolve/Executor/locator | 安全替换变量，调用 API 或页面动作，注册清理；不 eval 配置中的代码 |
| 环境边界 | framework/settings.py | 合并执行设置、解析相对 URL、限制允许访问的源 |
| 资源生命周期 | framework/fixtures.py、lifecycle.py | 创建独立 API/浏览器资源；清理回调在资源关闭前执行 |
| 底层能力 | framework/api_client.py、browser.py、assertions.py、steps.py、pages/base_page.py | 请求、浏览器启动、断言、步骤记录和 Python 页面对象基础 |
| 结果汇总 | framework/reporting/plugin.py | 模块/标签/范围筛选、读写策略、连通检查、三阶段合并、截图和中文输出 |
| 报告展示 | framework/reporting/builder.py、templates/report.html.j2 | 脱敏后生成中文 HTML/JSON，保留失败附件及过期报告清理 |
| 数据保护 | framework/security.py | 字段、环境凭证、URL 查询参数及动态提取密钥的日志脱敏 |

从菜单到报告的数据流：选择 → CLI 加载配置 → YAML 校验/收集 → 与 Python 用例一起筛选 → 连接检查 → 夹具初始化 → before → steps → cleanup → 资源关闭 → 合并准备/执行/清理结果 → 中文终端与报告。

源码中 `Executor` 先获取 API/页面夹具，再获取清理夹具，利用 Pytest 逆序释放机制保证清理请求有可用的上下文。变量属于单个 Executor；报告的 `_secrets` 仅用于内存脱敏，不写入最终 JSON。

## 8. 结果、排错与边界

报告路径仍为 `reports/<运行编号>/report.html`、`result.json`，保留现有中文结果、筛选、失败截图与 Trace。终端打印实际绝对路径。

- 0 条用例不是业务通过；无匹配模块返回退出码 5。
- 未启用、只读策略阻止的用例显示跳过；全部跳过会提示没有实际验证业务。
- 配置错误返回 4；业务断言失败返回 1；清理错误计入错误，不隐藏。
- 稳定定位、有效断言和独立测试数据比盲目增加等待更重要。
- 多模块目前按顺序执行，没有新增并行、自动重试、接口自动发现或录制生成；Web 管理平台已提供。
- iframe、上传下载、复杂签名、特殊认证、计算逻辑等使用原有 Python 扩展。
- 框架不会自动启动你的被测项目；本地服务应先启动，线上服务应事先确认目标环境。

开发验收的模拟服务、临时用例和临时报告完成后删除；你的业务用例、环境、凭证及已有正式报告保留。
