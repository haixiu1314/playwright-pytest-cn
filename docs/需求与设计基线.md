## 1. 项目目标

构建一个可重复使用的 Python 自动化测试项目，使用 Pytest 组织和执行用例，使用 Playwright 操作浏览器和调用 HTTP 接口。通过配置切换测试地址，支持验证本地开发项目、测试服务器项目和已部署的线上项目。

运行时用中文显示用例名称、执行进度和结果，明确显示“通过”“失败”“跳过”“错误”，运行结束后生成中文 HTML 报告。项目提供命令行入口；第一版无需额外开发 Web 管理后台。

本文件是后续开发的需求基线。仅交付文档不代表测试项目已经开发完成。

## 2. 已确认要求与实施约定

| 编号 | 要求 | 实施约定 |
| --- | --- | --- |
| R01 | 使用 Playwright + Pytest | Pytest 管理用例、夹具和断言；Playwright 提供浏览器操作及 APIRequestContext 接口请求能力 |
| R02 | 验证成功时显示通过 | 终端逐条输出中文状态；报告逐条展示结果和汇总 |
| R03 | 自动生成报告 | 默认生成中文 HTML 报告，附机器可读 JSON 结果 |
| R04 | 中文显示 | 自定义终端信息、报告、步骤说明、失败摘要使用中文；异常原文与技术标识保留便于排查 |
| R05 | 支持本地项目 | 通过配置访问本地 HTTP/HTTPS 服务，执行前检查连通性 |
| R06 | 支持服务器和线上项目 | 使用同一套执行机制，通过环境配置切换目标地址与认证 |
| R07 | 开发验证完成后删除 | 删除开发框架时临时创建的验证用例、模拟服务、测试数据和临时产物；保留正式框架和业务用例 |
| R08 | 不按某个测试项目命名每个接口功能 | 通用模块使用职责命名，业务用例按真实业务能力命名；不将演示项目名称写入接口、函数、菜单或报告模板 |
| R09 | 先提供文档 | 当前阶段只输出 Markdown 需求与设计文档，后续按本文件开发 |

对 R07 的具体解释：清理的是“开发过程中为了验证框架而临时产生的内容”。正式运行产生的报告属于交付结果，应按保留策略管理，不能生成后立即删除。清理失败需要中文提示，不能把残留问题隐藏为成功。

## 3. 测试范围

### 3.1 Web 页面自动化

支持打开页面、定位元素、填写表单、点击、等待页面状态，以及对页面地址、标题、文本、元素可见性和交互结果进行断言。支持失败截图及可选的 Playwright Trace，用于定位失败步骤。

定位优先使用角色、标签和稳定的 test-id。用例通过明确条件等待页面就绪，避免依赖固定休眠时间。

### 3.2 HTTP 接口自动化

支持 GET、POST、PUT、PATCH、DELETE 等请求方式，支持查询参数、JSON 请求体、请求头及认证。可验证状态码、响应字段、字段类型、业务值及必要的响应时间限制。

接口测试使用 Playwright APIRequestContext，不要求启动浏览器。接口响应快慢只能作为用例阈值检查；本项目第一版不承担负载测试或容量测试。

### 3.3 页面与接口联动

支持通过接口准备数据、通过页面验证结果，并在测试结束后清理数据。对同一个用户流程可以组合页面断言与接口断言，但报告应清楚说明各步骤验证了什么。

目标项目必须先提供实际业务信息，才能编写有意义的验证用例。仅检查网址可以打开，不代表业务功能验证通过。

## 4. 使用流程

1. 安装项目依赖和 Playwright 浏览器。
2. 配置目标环境的页面地址、接口地址和认证方式。
3. 根据目标项目编写或补充正式业务用例。
4. 使用中文说明的命令行入口，选择环境与测试范围。
5. 执行前验证配置和目标服务连通性。
6. 逐条显示中文结果，收集失败证据。
7. 执行数据清理，生成报告并输出报告位置。

本地服务默认由使用者自行启动。框架第一版不猜测业务项目的启动命令，不负责部署业务系统。

## 5. 技术架构

| 层次 | 职责 | 建议实现 |
| --- | --- | --- |
| 执行入口 | 环境选择、参数校验、执行和退出码 | Python CLI，调用 Pytest |
| 用例层 | 描述业务场景与预期结果 | Pytest 用例与参数化 |
| 页面层 | 封装页面定位和通用操作 | Playwright 同步 API 与 Page Object |
| 接口层 | 请求发送、认证、响应处理 | Playwright APIRequestContext |
| 断言与步骤层 | 中文断言信息、步骤记录 | 通用断言辅助函数与步骤上下文 |
| 生命周期层 | 浏览器隔离、数据准备及清理 | Pytest fixtures 与 finalizer |
| 报告层 | 汇总结果、生成中文页面 | Pytest hooks、结果模型、Jinja2 模板 |

建议 Python 3.11 及以上，依赖在实现时选择经过兼容验证的版本并锁定。第一版使用同步 API、串行执行、Chromium 浏览器，降低配置和维护成本。Firefox、WebKit、并行执行及 CI 集成为后续扩展项。

中文报告使用自有模板，避免依赖第三方报告界面是否完整支持中文。报告中的技术异常原文、HTTP 字段名、路径及 Playwright Trace 工具自身界面不强行翻译。

```text
│   ├── assertions.py
│   ├── steps.py

│       ├── plugin.py
│       ├── models.py
│       └── templates/report.html.j2
├── pages/

│   ├── api/

│   └── workflows/
├── reports/
└── .runtime/
```

通用接口采用 `request`、`get`、`post`、`assert_status` 等职责名称。正式业务用例按实际功能命名，例如 `test_create_record`，展示标题使用“创建记录后返回正确状态”。这些名称只说明命名规则，不代表需要保留演示业务。

一个被测项目中可以包含多条接口与页面用例，无需为每个接口单独创建一个“测试项目”。报告的项目名称由配置统一指定，不硬编码到框架函数名中。

开发期间的临时验证内容统一放在 `.runtime/verification/<run_id>/` 下，验证完成即清理。正式 `tests/` 目录中只保留用于长期执行的业务用例。

## 7. 环境配置设计

```yaml
project_name: 通用自动化测试
default_environment: local

environments:
  local:
    web_base_url: http://127.0.0.1:3000
    api_base_url: http://127.0.0.1:8000
    allow_write: true
    verify_tls: true
  staging:
    web_base_url: https://staging.example.com
    api_base_url: https://api-staging.example.com
    allow_write: true
    verify_tls: true
  production:
    web_base_url: https://example.com
    api_base_url: https://api.example.com
    allow_write: false
    verify_tls: true

execution:
  browser: chromium
  headless: true
  timeout_ms: 15000
  retries: 0

report:
  locale: zh-CN
  directory: reports
  screenshot_on_failure: true
  trace: retain-on-failure
  retention_days: 7
```

以上地址为配置示意，开发时不把它们当作实际测试目标。页面与接口可使用相同或不同域名；只执行一种测试时，仅要求对应地址有效。

认证信息通过环境变量提供，例如 `AUTOMATION_TOKEN`、`AUTOMATION_USERNAME`、`AUTOMATION_PASSWORD`，配置文件不保存真实密码。框架允许配置 Bearer Token、Cookie 或登录夹具，具体方式以被测系统为准。目标存在验证码或 MFA 时，需要提供适合自动化的测试账号或既有登录状态。

相对路径按所选环境地址解析，检查最终请求及页面导航的目标地址。默认不允许用例意外访问其他环境；必要的跨域服务需要显式配置允许列表。线上环境默认仅执行标记为只读的用例，写入类用例需显式启用并具备数据隔离和清理方案。

## 8. 对外使用入口

以下是计划实现的 CLI 契约，当前不是可运行命令。

```bash
# 本地：执行所有已配置业务用例
python -m framework.cli --env local

# 服务器：只执行接口测试
python -m framework.cli --env staging --scope api

# 线上：只执行只读页面用例
python -m framework.cli --env production --scope web --read-only

# 显示浏览器窗口，便于观察
python -m framework.cli --env local --scope web --headed

# 指定报告输出目录
python -m framework.cli --env local --report-dir reports/manual-run
```

| 参数 | 含义 | 默认行为 |
| --- | --- | --- |
| `--env` | 目标环境 | 使用配置的默认环境 |
| `--scope` | `api`、`web`、`workflows` 或 `all` | `all` |
| `--headed` | 显示浏览器窗口 | 无头执行 |
| `--read-only` | 只选择只读用例 | 线上环境默认启用 |
| `--allow-write` | 显式允许写入类用例 | 默认不启用；仍需环境允许写入 |
| `--report-dir` | 报告输出根目录 | `reports` |

配置错误时立即中文报错；没有选中用例时显示“未发现可执行用例”，不能显示为全部通过。`--allow-write` 与 `--read-only` 同时传入应报参数冲突。

退出码沿用 Pytest：0 为所选用例执行完成且无失败，1 为用例失败，2 为执行中断或收集错误，3 为内部错误，4 为参数使用错误，5 为没有收集到用例。自定义配置和参数错误使用 4。全被跳过时额外显示“未实际验证业务”，避免将其解读为业务通过。

## 9. 内部接口设计

这里的接口指测试框架的 Python 调用契约，不是新增对外 HTTP 服务。

| 接口 | 主要输入 | 返回或作用 |
| --- | --- | --- |
| `load_settings(env_name)` | 环境名称 | 校验后的环境和执行配置 |
| `ApiClient.request(method, path, **kwargs)` | 方法、路径、参数 | 请求响应，记录脱敏后的步骤信息 |
| `assert_status(response, expected)` | 响应、预期状态码 | 失败时抛出含中文信息的断言异常 |
| `assert_json_value(response, path, expected)` | 响应、字段路径、预期值 | 验证 JSON 字段，失败时说明差异 |
| `step(title)` | 中文步骤标题 | 记录步骤状态、耗时及异常 |
| `cleanup_registry.register(callback)` | 清理回调 | 登记资源清理动作 |
| `build_report(run_result, output_dir)` | 结构化结果、目录 | 生成 HTML 与 JSON 文件 |

JSON 字段路径第一版支持字典键与数组下标，例如 `data.items[0].id`；不声称支持完整 JSONPath。字段缺失、响应不是 JSON 或路径无效时，应给出中文原因。

### 9.1 Pytest 夹具

| 夹具 | 作用域 | 职责 |
| --- | --- | --- |
| `settings` | session | 提供当前环境配置 |
| `api_client` | function | 独立请求上下文，结束后释放 |
| `page` | function | 独立浏览器上下文和页面，结束后关闭 |
| `cleanup_registry` | function | 按登记逆序清理数据，汇总清理失败 |

用例不依赖其他用例的执行顺序。需要复用登录状态时，显式通过夹具加载，避免复用可变页面造成状态串扰。

### 9.2 用例标记

使用 `api`、`web`、`workflow` 区分执行范围，使用 `readonly`、`write` 区分业务影响。未声明业务影响的用例默认不纳入线上执行，并显示中文原因。

中文标题存储在自定义 `title` 标记中，参数化用例使用可读的中文参数说明。函数名保持合法 Python 标识符，报告标题与函数标识分开存储。

## 10. 中文结果与报告

### 10.1 终端输出示意

```text
目标环境：本地环境
执行范围：接口与页面
已收集：3 条用例

[通过] 记录列表返回正确状态（0.18 秒）
[通过] 首页显示预期标题（1.26 秒）
[失败] 提交空表单时显示校验提示（2.04 秒）
  原因：预期显示“必填”，实际未找到对应提示。

执行完成：共 3 条，通过 2 条，失败 1 条，跳过 0 条，错误 0 条。
报告：reports/<run_id>/report.html
```

以上仅展示输出格式，不是已经执行的结果。

### 10.2 状态规则

| 状态 | 判定方式 |
| --- | --- |
| 通过 | 准备、测试主体、清理均成功，且预期断言全部成立 |
| 失败 | 测试主体断言不满足或执行出现异常 |
| 错误 | 准备或清理阶段失败、执行基础设施异常 |
| 跳过 | 用例主动跳过或被环境规则限制，并给出原因 |
| 预期失败 | Pytest xfail，用于说明已知问题，不计入普通通过 |
| 意外通过 | 严格 xfail 场景实际通过，应提示更新已知问题并按失败处理 |

以用例为单位汇总，保留 setup、call、teardown 各阶段明细。主体通过但清理失败时，最终状态为“错误”；主体失败且清理也失败时保留两项原因，最终状态为“错误”，避免重复计数。完成 teardown 后再输出最终“通过”。

### 10.3 HTML 报告内容

报告展示项目名称、环境、脱敏后的目标地址、运行编号、开始和结束时间、耗时、各状态数量、用例明细、步骤、断言差异、失败截图及可选 Trace 附件。时间附带时区，避免本地和服务器时间混淆。

报告支持按状态和用例名称筛选。页面文本和状态以中文呈现，HTML 使用 UTF-8。基础样式与脚本随报告保存，不依赖外部 CDN。复制整份报告目录后，应能离线打开 HTML 并查看截图。Trace 为诊断附件，通过 Playwright 工具查看，不要求在 HTML 内离线直接播放。

通过率定义为“普通通过数 ÷（普通通过数 + 失败数 + 错误数）”，跳过和预期失败单独展示；分母为零时显示“无可统计结果”。意外通过计入失败统计。

JSON 结果至少保存 `run_id`、`environment`、`started_at`、`finished_at`、`summary` 和 `cases`。每个用例包含 `id`、`title`、`status`、`duration_ms`、`steps`、`phase_results`、`error`、`attachments`，便于后续 CI 集成。内部状态可使用稳定英文枚举，由界面映射为中文。

### 10.4 信息处理

请求记录隐藏 Authorization、Cookie、密码和 Token。响应内容限制长度，并支持增加敏感字段规则。截图和 Trace 可能包含业务信息，因此仅在需要时采集，默认保留失败证据；测试账号和数据选择应避免包含真实敏感内容。报告中对异常文本、响应值和用例名称进行 HTML 转义，防止内容被当成页面脚本执行。

## 11. 开发验证与清理规则

框架开发时可临时搭建本地页面和模拟接口，验证通过、失败、跳过、异常、中文编码和报告流程。这些内容只用于验证框架，不作为最终业务项目交付。

完成验证后执行以下清理：

1. 停止本轮启动的模拟服务和浏览器进程。
2. 删除本轮临时验证用例、页面、接口数据和配置。
3. 删除开发验证产生的临时报告、截图、Trace、缓存与登录状态文件。
4. 检查正式目录未残留演示项目名称、验证入口或硬编码目标地址。
5. 在交付说明中简述已验证的能力与清理结果，不保留临时测试项目。

正式运行期间，测试数据通过专用标识绑定当前运行，仅清理由当前运行创建的数据。清理必须限制在明确的运行目录或已登记资源内，不使用宽泛通配符删除业务文件或服务端记录。

正式报告默认保留 7 天，可配置更长时间。定期清理只处理报告根目录内由框架创建的历史运行目录，最新一次正式报告始终保留。开发验证报告不受此保留要求约束，应在验证结束时删除。

## 12. 验收标准

| 编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| A01 | 通过配置切换本地与远程环境 | 框架代码不需要修改，测试地址正确切换 |
| A02 | 页面用例断言成立 | 终端和 HTML 均显示中文“通过” |
| A03 | 接口状态码或字段不符合预期 | 显示“失败”，中文说明预期值和实际值 |
| A04 | 页面断言失败 | 生成失败截图，报告可查看对应附件 |
| A05 | 数据准备或清理失败 | 显示“错误”，不显示最终通过 |
| A06 | 正常结束或出现一般用例失败 | 生成可打开的中文 HTML 和结构化 JSON |
| A07 | 未发现用例或全部跳过 | 明确提示未实际验证业务，不给出业务全通过结论 |
| A08 | 线上只读模式 | 写入用例不执行，报告说明限制原因 |
| A09 | 中文标题、参数和异常 | UTF-8 显示正常，不出现乱码 |
| A10 | 开发验证完成 | 临时用例、服务、数据、报告与附件已清理 |
| A11 | 通用模块与接口名称 | 不包含某个演示测试项目名称 |
| A12 | 报告包含认证字段或特殊文本 | 敏感字段脱敏，HTML 内容正确转义 |

进程被强制终止、系统断电或磁盘写入失败时，无法保证最终 HTML 完整生成。正常异常路径应尽量保存已有结果，并明确提示报告生成失败及原因。
